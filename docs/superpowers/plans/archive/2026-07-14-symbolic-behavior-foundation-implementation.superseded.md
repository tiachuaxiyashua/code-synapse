# Superseded Symbolic Behavior Foundation Implementation Plan

> **Status:** Superseded by `docs/superpowers/plans/2026-07-14-core-feasibility-experiment.md`. The Ponytail review rejected this plan because it built a broad production foundation before testing whether CodeGraph evidence plus AI semantics can produce a faithful, comprehensible, progressively drillable human model.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first production vertical slice that invokes CodeGraph, reads `.codegraph/codegraph.db` directly and read-only, extracts deterministic TypeScript/JavaScript and Python control flow plus selector propagation, and persists queryable symbolic behavior artifacts.

**Architecture:** Keep one TypeScript package until real deployment boundaries require a split. CodeGraph remains an external CLI and rebuildable structural cache; small adapters convert its SQLite rows and language ASTs into Code Synapse-owned schemas, then an application pipeline atomically writes `.code_synapse/` artifacts. The slice ends at a CLI/query contract so later AI enrichment, Skills, and independent web views all consume the same model.

**Tech Stack:** Node.js 22.22+, TypeScript 7, npm, Vitest, `better-sqlite3`, `@ast-grep/napi`, `@ast-grep/lang-python`, Zod, Commander.

**Ponytail Gate:** Pending. This plan predates the mandatory design gate and must not be executed until a `ponytail` full review simplifies or explicitly retains its scope and changes this line to `passed` with a one-line result.

## Scope And Delivery Order

This plan implements Milestone 1 only. It deliberately proves the truth-preserving analysis path before spending time on AI prompts or diagram rendering.

| Order | Milestone | Exit condition |
| --- | --- | --- |
| 1 | Symbolic behavior foundation | TS/JS and Python fixtures produce versioned behavior files with branches, selectors, bindings, implementation evidence, `analysis-gap`, and `external-boundary` |
| 2 | Semantic enrichment | Bounded evidence packs produce schema-valid purpose, feature ownership, terminology, and branch classification in the project's chosen language |
| 3 | Hierarchical scopes | Capability/use-case trees and parent/child flows can navigate to terminal implementation groups without inlining the whole call graph |
| 4 | First usable web surface | Separate feature, flow, and code-detail URLs consume the query API; named-window reuse, always-new-window mode, hover-follow, pin, and drill-down work end to end |
| 5 | Specialized projections | C4 architecture, BPMN/sequence/dataflow routes, Perfetto runtime tracks, and WaveDrom timing are added only for mechanisms with sufficient evidence |
| 6 | Change and conflict model | Before/after behavior graphs explain added, removed, and changed behavior and evidence-backed conflicts |
| 7 | Agent integration and packaging | Author and Bootstrap Skills, Codex/Claude entry points, automatic CodeGraph setup, local server packaging, migrations, and release checks are complete |

Milestones 2-7 each require their own implementation plan after the preceding exit condition passes. The current open visual questions in `docs/design/product.md` must be resolved with focused renderer prototypes before Milestones 4-5 are planned.

The workspace is not currently a Git repository, so this plan does not include nonfunctional commit steps. Initialize version control as a separate explicit operation before execution if project history is desired.
