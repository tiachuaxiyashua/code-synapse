# 一期手动测试方案

## 1. 目的与角色

手测分三种角色，不能由同一个开发者自问自答后宣称通过：

- **事实审查者**：能读 TypeScript，核对图、CodeGraph 和源码；
- **目标用户**：不懂编程或代码能力较弱，验证是否真的理解；
- **交互观察者**：记录操作困难、误解和引导行为，不提示正确答案。

## 2. 环境

- macOS/Windows 任一桌面环境；
- Chromium 最新稳定版；
- 1280x720 和 1440x900 两种视口；
- 从功能树 URL 开始；
- 清空先前窗口选择状态；
- 目标用户不得先看样例源码或正确答案。

## 3. 事实真实性审查

事实审查者逐项填写 `通过/失败/证据/备注`：

| 编号 | 检查 |
| --- | --- |
| MT-TRUTH-01 | 每个 Z0 功能和关系至少有一条精确证据 |
| MT-TRUTH-02 | 注册入口、调用顺序、成功结果和失败结果与源码一致 |
| MT-TRUTH-03 | 登录的成功/失败条件与源码一致，没有把候选关系画成无条件调用 |
| MT-TRUTH-04 | 参数、返回值和事件名称、方向、用途与源码一致 |
| MT-TRUTH-05 | Z1/Z2 没有添加源码不存在的步骤 |
| MT-TRUTH-06 | 主路径没有为了简洁而遗漏关键步骤 |
| MT-TRUTH-07 | 源码抽屉路径、行号、片段与固定提交一致 |
| MT-TRUTH-08 | 无法解析的内部逻辑标为分析缺口，仓库外实现标为外部边界 |

任一 MT-TRUTH 失败即不能 GO。

## 4. 目标用户任务

观察者只读任务，不解释术语。

### 任务 A：找到并概括功能

1. 找到“注册”功能并打开其流程。
2. 不放大，说明这个功能从哪里开始、做了哪几件主要事情、最后可能有什么结果。

通过：用户能指出入口、两个以上主要步骤、成功和失败结果。

### 任务 B：逐级理解

1. 使用滚轮查看下一层。
2. 说明新出现的细节分别属于哪个上层步骤。
3. 继续查看最细层，再回到总览。

通过：用户能说出至少两个父子归属，返回总览后仍能定位刚才的实现位置。

### 任务 C：理解选择

1. 找到登录成功和登录失败路径。
2. 说明各自由什么条件触发，会产生什么结果。

通过：条件和结果均正确，不把未绑定分支理解成随机概率。

### 任务 D：理解传递

1. 找到一次函数间的数据传递。
2. 找到注册完成后的事件传递。
3. 说明谁把什么交给谁，为什么要交。

通过：方向、内容和用途均正确。

### 任务 E：核查证据

1. 悬浮查看一个步骤说明。
2. 点击固定，移动鼠标后打开实现。
3. 关闭源码抽屉并继续浏览。

通过：用户能指出说明对应的文件/代码；关闭后视口、层级和选择未丢失。

## 5. 交互检查

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| MT-UX-01 | 快速滚轮跨阈值 | 层级稳定，无反复闪烁 |
| MT-UX-02 | 中键拖动画布 | 只平移，不选中节点、不改变层级 |
| MT-UX-03 | 在四个视口边缘 hover | 说明不出屏，尽量不遮挡对象 |
| MT-UX-04 | 固定后点击图外/Escape | 固定态明确并可取消 |
| MT-UX-05 | 打开关闭抽屉 | 图自适应且不重置状态 |
| MT-UX-06 | 缩小隐藏选中子节点 | 最近可见祖先保持选中提示 |
| MT-UX-07 | 功能树和流程并排 | 选择同步，流程窗口相机独立 |
| MT-UX-08 | 两种目标视口 | 无按钮/文本重叠，无空白画布 |

## 6. 与旧原型对照

目标用户分别用旧的点击进入下层方式和新语义缩放方式完成以下任务，并选择 `更容易/相同/更困难`：

- 记住细节属于全局流程的哪里；
- 在总览与实现之间往返；
- 比较相邻分支或步骤；
- 理解关系上传递的数据或事件。

GO 要求新方式没有任何一项更困难，且至少三项更容易。
